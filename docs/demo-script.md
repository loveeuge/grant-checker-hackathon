# 90초 발표 스크립트와 데모 순서

## 90초 발표 스크립트

**0-15초: 문제 제기**

"지원사업을 준비하는 초기 팀은 공고문, 서류 양식, 예산 제한, 개인정보 문구를 하나씩 대조해야 합니다. 문제는 대부분 마감 직전에 누락 서류나 조건 오독을 발견한다는 점입니다."

**15-30초: 아이디어**

"저희 MVP는 지원사업 공고문, 팀 정보, 준비 서류 목록을 입력하면 1페이지 제출 전 체크리스트를 만들어 줍니다. 목표는 자동 심사가 아니라, 제출 전에 사람이 놓치기 쉬운 항목을 빠르게 정리하는 것입니다."

**30-50초: 오늘 만든 범위**

"오늘 데모에서는 가상 공고문과 가상 팀 데이터를 사용합니다. OpenAI API로 마감일, 누락 서류, 예산 제한, 개인정보 설명 필요 항목을 추출하고, 사람이 최종 확인해야 할 질문 형태로 보여줍니다."

**50-70초: 안전 경계**

"중요한 점은 이 도구가 실제 제출, 개인정보 저장, 자동 합격/불합격 판단을 하지 않는다는 것입니다. API key는 관리자가 로컬 환경에만 입력하고, 데모 데이터에는 실제 개인정보를 넣지 않습니다."

**70-90초: 마무리**

"결과적으로 이 도구는 지원사업 제출 전 마지막 30분의 불안을 줄이는 체크 파트너입니다. 오늘은 1페이지 체크리스트 생성에 집중했고, 이후에는 기관별 양식 매핑과 협업 리뷰 기능으로 확장할 수 있습니다."

## 심사위원 데모 순서

1. 앱을 실행하고 샘플 데이터가 들어간 화면을 보여줍니다.
2. 공고문 입력 영역에 `data/sample.json`의 가상 공고문이 들어가 있음을 보여줍니다.
3. 팀 정보 영역에서 "체크메이트 랩스"가 예비창업팀이고, 실제 개인정보가 아닌 가명만 사용한다는 점을 짧게 언급합니다.
4. 준비 서류 목록을 보여주며 `ready`, `draft`, `missing`, `not-for-demo` 상태가 섞여 있음을 확인시킵니다.
5. "체크리스트 생성"을 실행합니다.
6. 결과 화면에서 누락 서류 2개를 강조합니다: 개인정보 수집 및 이용 동의서, 사업자등록증 또는 예비창업 확인서.
7. 사업계획서 보강 항목을 보여줍니다: 데이터 출처, 개인정보 비식별 처리, AI 결과 검수 절차.
8. 예산 검토 항목을 보여줍니다: 장비 구매 항목이 총 사업비 20% 이내인지 확인.
9. 안전 문구를 읽어 줍니다: AI는 신청 자격을 확정하지 않고, 공고문 원문과 접수 시스템 양식은 사람이 최종 확인합니다.
10. 오늘 제외 범위를 다시 말합니다: 실제 제출, 개인정보 저장, 자동 판단은 하지 않습니다.

## 데모 중 사용할 한 문장

"이 화면은 합격 가능성을 점수화하는 화면이 아니라, 제출 전에 사람이 확인해야 할 위험 항목을 한 장으로 모으는 화면입니다."

## 예상 질문 답변

**Q. 실제 지원사업에 바로 제출할 수 있나요?**

"아니요. 오늘 MVP는 제출 전 체크리스트 생성까지만 합니다. 실제 접수, 파일 업로드, 전자서명은 제외했습니다."

**Q. 개인정보는 어떻게 처리하나요?**

"데모에는 가명 데이터만 사용합니다. 실제 서비스에서도 개인정보 원문 저장 없이 세션 단위 분석과 최소 수집을 우선합니다."

**Q. AI가 지원 가능 여부를 판단하나요?**

"아니요. 자동 합격/불합격 판단은 하지 않습니다. 대신 공고문 근거와 함께 사람이 확인해야 할 질문을 보여줍니다."
